# Scheduled reorganization pull request (optional)

A workflow in `<org>/.github` that, once a week, opens a pull request proposing changes to `repo-groups.yml`. It is off until an org copies it, and it never changes anything on its own: a person reviews and merges the pull request.

## Files

| File | What it is |
|---|---|
| `design/actions/repo-groups-reorg.yml` | Workflow template (weekly cron, `workflow_dispatch` with a `dry_run` input) |
| `design/actions/reorg.mjs` | One self-contained Node script (no `npm install`), generated by `npm run build:action` from `src/core` and `src/action`. A test fails when it is out of sync |

Install: copy the template to `<org>/.github/.github/workflows/repo-groups-reorg.yml` and the script to `<org>/.github/.github/scripts/reorg.mjs`, then create the secret `REPO_GROUPS_TOKEN`.

## What a run does

1. Reads `repo-groups.yml` from the default branch of `<org>/.github` and lists the organization's repositories (archived ones are ignored for placement).
2. Places every repository with the same algorithm as the extension (CLAUDE.md §5.3).
3. Finds new repositories that no group catches and exact names in `match` whose repository no longer exists (an archived repository still exists, so its name is kept).
4. For a new repository it adds the exact name to a group only when the lexical suggestion (`src/core/suggest.ts`) is confident. The others are listed in the pull request under **Needs a human decision**.
5. Dead exact names are proposed for removal, inside the pull request only.
6. Writes the canonical YAML, commits `chore(repo-groups): propose reorganization (N changes)` on the branch `repo-groups/reorg-<date>`, and opens a pull request whose body lists the changes (`+`, `−`, `~`, `→`).

Guarantees:

- It never pushes to the default branch and never deletes a branch, repository or file.
- If a reorganization pull request is already open, the run updates that branch and pull request instead of opening another. If nothing changed since, it writes nothing.
- With no changes it opens no pull request. Repositories that only need a human decision do not open one by themselves; they are listed the next time there is a change.
- If the token lists no repositories the run stops, so a broken token never proposes removing every name.
- The file is rewritten in canonical format, so comments and unknown keys are dropped (same as saving from the extension).

## Dry run

Run the workflow manually with `dry_run` on. The log prints the pull request body and the proposed file, and nothing is written. Locally: `ORG=acme REPO_GROUPS_TOKEN=... DRY_RUN=true node design/actions/reorg.mjs`.

## Token and privacy

`REPO_GROUPS_TOKEN` (org secret available to `<org>/.github`; fine-grained token or GitHub App token):

- Repository **Metadata: Read** on all repositories of the org, to list them.
- Repository **Contents: Read & write** and **Pull requests: Read & write** on `<org>/.github`.

A pull request opened with a personal or App token triggers other workflows; one opened with the built-in `GITHUB_TOKEN` would not, and it cannot see private repositories.

**Privacy:** the pull request body names repositories and their descriptions, including private ones the token can see. Everyone who can read `<org>/.github` can read the pull request. Enable it only where members already see every repository, as with the `index: action` index.

The script talks only to `api.github.com`. No data goes anywhere else.
